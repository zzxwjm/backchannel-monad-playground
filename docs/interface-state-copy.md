# Bonded Agent 界面状态与文案规范

**目的：** 让用户在签名前知道谁承担什么责任，并让页面文案永远与链上事实一致。  
**适用对象：** Dev 2、设计、Research。

## 1. 首页报价状态

| 元素 | 文案 | 数据来源 / 规则 |
| --- | --- | --- |
| 标题 | 有担保的 Swap | 固定 |
| 副标题 | Agent 运营方为交易结果锁定保证金；在保障范围内，结果不足时自动补足。 | 不使用“保证盈利” |
| 输入 | 输入金额（MON） | 只允许 P0 支持的数值 |
| 目标代币 | tUSDC（固定） | P0 固定 |
| 主按钮 | 获取担保报价 | 只有有效金额时可点击 |
| 报价标签 | 演示报价，非真实汇率 | MockDex 未替换前必须显示 |

**金额格式要求：** 使用代币 `decimals()` 格式化；去除无意义的尾随零；超过可读长度时使用千分位或科学计数法，不显示原始最小单位。

## 2. 报价预览状态

必须同时展示：预期输出、保证输出、运营方锁定保证金、最大赔付、有效期。每个值都应带上代币单位。

辅助文案：

> 保证输出不是盈利承诺。若结果处于可保障范围内，合约自动补足至保证输出；若价格跌破可保障范围，交易安全失败并按条款退款与补偿。

主按钮：`生成担保计划`。

在演示模式下，卡片顶部使用黄色/灰色 badge：`演示数据，尚未上链`。不得在此阶段写“运营方已锁定保证金”。

## 3. 待签名 / 已上链计划

| 状态 | Badge | 主按钮 | 允许使用的事实陈述 |
| --- | --- | --- | --- |
| 演示计划 | 演示，未上链 | 查看演示结果 | 不产生真实交易 |
| 等待用户签名 | 待执行 | 同意并执行 Swap | 计划已创建；仅在 `PlanOpened` 已确认后才可说保证金已锁定 |
| 执行中 | 交易确认中 | 禁用 | 正在等待链上确认 |
| 过期 | 已过期 | 禁用 / 获取新报价 | 本计划已过期，不能执行 |

计划卡必须包含：交易摘要、保证输出、锁定保证金、最大赔付、失败补偿、截止时间、风险边界、计划 ID。地址、calldata 哈希、nonce 可收进“技术详情”。

## 4. 结算状态

| 结果 | 页面标题 | 结算说明 |
| --- | --- | --- |
| 正常履约 | 本计划已结算 | 执行成功，到账 `actualOutput tUSDC`，达到保证输出；运营方保证金已释放。 |
| 自动赔付 | 已自动补足 | 原始到账 `actualOutput tUSDC`，合约自动赔付 `compensation tUSDC`；你最终收到 `guaranteedOutput tUSDC`。 |
| 安全失败 | 已退款并补偿 | 结果超出可保障范围或 Swap 调用失败；输入已退回，并收到 `failureCompensation tUSDC` 补偿。 |
| 过期 | 本计划已过期 | 未发生 Swap；请获取新报价。 |

每个真实 Testnet 结算页必须提供：`查看交易详情`、交易 Hash 复制按钮、合约地址链接。演示模式只可写“演示数据”，不能伪造 Explorer 链接。

## 5. 风险边界固定文案

- 本计划只保证这一笔 Swap 的最低到账，不保证盈利。
- 仅当实际到账处于可保障范围内时，合约自动补足差额；赔付上限为已锁定保证金。
- 当前市场为模拟 `MockDex`，汇率由团队配置，不是实时 DEX 报价。
- 使用的是 Monad Testnet 和测试资产，无真实价值。

## 6. 当前页面必须修正的内容

- 报价预览页出现的原始单位数字，例如 `950000000000000000 tUSDC`，必须修复为人类可读的 `0.95 tUSDC`。
- 在没有真实 `PlanOpened` 事件时，将“运营方已锁定保证金”改为“计划要求锁定保证金”或“演示保证金”。
- 将“保证输出”附近加入一行“可保障范围下限”，或在风险边界中明确写出超出赔付上限时会安全失败。
- 演示计划的“同意并执行 Swap”应改成“查看演示结算”，或在按钮旁显著标注“不发起链上交易”。
