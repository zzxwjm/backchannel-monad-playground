# Bonded Agent：五天执行计划

**项目名称：** Bonded Agent  
**团队名称：** Backchannel  
**开发周期：** 5 天  
**参赛方向：** Monad Playground 开放方向；Moss 为条件性集成项  
**范围决定：** 只实现一个具有客观判断标准的 Swap 结果担保，不做通用承诺协议。

## 一、产品定义

### 一句话介绍

Moss 可以解释 Agent 预计一笔交易会产生什么结果；Bonded Agent 进一步要求 Agent 运营方为这个预期结果锁定保证金。如果实际执行结果低于承诺，合约自动向用户赔付。

### 目标用户

愿意让 AI Agent 准备链上交易，但不愿仅凭 Agent 的解释或模拟结果就承担全部风险的普通链上用户。

### 解决的问题

模拟只能说明交易在某个时刻和某种状态下可能产生什么结果，并不是保证。模拟完成后，链上状态和价格可能在用户签名前发生变化。目前即使 Agent 给出的结果没有兑现，Agent 运营方通常也不承担经济责任。

### 核心用户流程

1. 用户提出固定请求，例如“把 1 MON 换成 tUSDC”。
2. Agent 构造并模拟交易。
3. Agent 运营方发布一份交易计划，写明预期输出、保证输出、最大赔付、有效期、目标合约和 calldata 哈希。
4. Agent 运营方为该计划锁定 tUSDC 保证金。
5. 用户查看交易计划与保证条款，决定是否签名。
6. `BondedExecutor` 执行 Swap，并测量用户实际获得的 tUSDC。
7. 实际输出达到保证值时，剩余保证金退还运营方。
8. 实际输出低于保证值、但仍在保障范围内时，合约从保证金中自动补足差额。
9. Swap 调用失败时，合约退还用户输入，并支付预先约定的失败补偿。

## 二、项目边界

### P0：必须完成

- [ ] 只支持一种交易：测试网原生 MON 换取测试代币 `tUSDC`。
- [ ] 只支持一个由团队控制的 Agent 运营方。
- [ ] 在 Monad Testnet 部署一个真实运行的 `BondedExecutor`。
- [ ] 交易计划必须包含用户、资产、金额、保证结果、最大责任、目标合约、calldata 哈希、有效期和 nonce。
- [ ] 在 Monad Testnet 真实完成保证金锁定、释放和自动赔付。
- [ ] 分别完成“正常履约”和“结果不足自动赔付”两个链上案例。
- [ ] 防止计划过期、重复执行、保证金不足和 calldata 被替换。
- [ ] 用户签名前必须看到清晰的承诺卡片。
- [ ] 结算后展示交易链接和普通语言解释。
- [ ] 完成合约测试，并进行至少 3 次可用性测试。
- [ ] 提供 README、架构图、风险说明以及真实/模拟功能披露。

### P1：P0 稳定后才允许开发

- [ ] 真正接入 Moss 的 `discover -> load -> action -> simulate` 流程。
- [ ] 使用 EIP-712 离线承诺签名代替运营方链上创建计划。
- [ ] 接入真实 Monad DEX。
- [ ] 增加担保服务费。
- [ ] 支持多个 Agent 运营方及运营方声誉。

- 由 LLM 或管理员判断是否违约。
- 保险池、跨链、治理或发币。

## 三、技术设计

### P0 合约

**`MockUSDC.sol`**

- 作为测试输出资产和 Agent 运营方的保证金资产。
- 固定小数位；仅允许测试部署者铸造。

**`MockDex.sol`**

- 接收测试 MON，并按可配置测试汇率返回 tUSDC。
- 支持最低输出；当价格超出保证金覆盖范围时安全失败。
- 可配置价格属于模拟市场组件，必须在产品和 README 中明确标注。

**`BondedExecutor.sol`**

- 创建一次性担保计划并锁定最大赔付责任。
- 将计划绑定到特定用户、目标合约、calldata 哈希、有效期和 nonce。
- 执行目标合约调用。
- 测量输出代币余额变化。
- 从保证金中支付保障范围内的差额。
- 在外部调用失败时保留退款与赔付状态，不能因为整体回滚导致无法补偿。
- 产生 `PlanOpened`、`PlanExecuted`、`ShortfallPaid`、`PlanFailed` 和 `BondReleased` 事件。

### 最小计划结构

```solidity
struct Plan {
    address user;
    address operator;
    address outputToken;
    uint256 inputAmount;
    uint256 expectedOutput;
    uint256 guaranteedOutput;
    uint256 maxCompensation;
    uint256 failureCompensation;
    address target;
    bytes32 calldataHash;
    uint256 deadline;
    uint256 nonce;
}
```

### 必须覆盖的合约测试

- [ ] 实际输出高于保证值：不赔付，保证金释放。
- [ ] 实际输出低于保证值：精确补足差额。
- [ ] 差额等于最大赔付：使用全部允许的保证金。
- [ ] 价格超出覆盖范围：Swap 安全失败，用户输入退回。
- [ ] 目标合约或 calldata 被修改：拒绝执行。
- [ ] 计划过期：拒绝执行。
- [ ] nonce 或计划被重复使用：拒绝执行。
- [ ] 运营方保证金不足：无法创建计划。
- [ ] 非指定用户尝试执行：拒绝执行。
- [ ] 覆盖重入和代币转账失败路径。

## 四、完成标准

只有以下条件全部成立，项目才算完成：

- [ ] 新用户连接课程/测试钱包后，能在签名前理解保证条款。

- [ ] 结果不足案例无需管理员判断即可自动赔付。
- [ ] 前端读取真实合约事件，不使用硬编码结果。

- [ ] 产品和 README 都明确标注真实与模拟部分。
- [ ] 备用视频完整展示正常履约与自动赔付。

## 七、最终 Demo 剧本

1. 用户要求把 1 MON 换成 tUSDC。
2. 展示模拟结果、运营方保证输出和锁定保证金。
3. 完成一次正常执行，展示保证金释放。
4. 明确展示模拟市场价格发生变化。
5. 执行第二份计划，展示差额自动赔付。
6. 在区块浏览器中打开两组交易。
7. 最后说明边界：合约只保证一个可测量结果，不保证盈利，也不证明 Agent 在所有任务中都正确。

## 八、停止条件

出现以下任一情况，立即停止加功能并简化：

- 赔付依赖管理员或 LLM 判断是否违约。
- 无法通过链上代币余额变化测量差额。
- 无法防止重放或 calldata 被替换。
- 前端展示的保证没有足额保证金支持。
- Moss 集成威胁正常履约和赔付两个 P0 流程。
- 团队无法准确解释哪些市场行为属于模拟。
